# Specification compliance

Review behavior against the applicable user requirements, issue, PR description, or specification. Latest explicit user requirements take precedence over stale task or spec text.

Useful investigation angles:
- missing or partial required behavior
- behavior outside the agreed scope
- acceptance criteria or explicitly required scenarios left unmet
- inconsistent interpretation of domain terms
- implementations that appear compliant but fail a concrete scenario

Cite the requirement and the implementation path or missing behavior that violates it. Do not invent requirements. Treat unresolved ambiguity or conflicting requirements as a question, not a proven defect.
